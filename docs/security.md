# 安全边界与待验证机制

本文件将必须保持的安全边界与可能实现这些边界的机制分开。**已确认的不变量不是已实现的防护，候选机制也没有已确认的技术 Pass。** 当前证据和授权状态以[工程状态](project-status.md)为准。

## 为什么需要可信与不可信分离

项目文件、Rules / Skills、工具返回或模型建议可能包含越权指令。Hub 因此必须在真实执行处控制权限，不能依靠提示词要求 Agent 自律。

自有 Harness 是当前优先方向，使 Hub 能直接设计运行循环；这不构成已验证隔离。已有 Agent 的后续接入须单独检验其是否能绕过 Hub，不能继承自有 Harness 的控制假设。运行模式见[架构](architecture.md#三种运行模式与优先级)。

### 已确认的安全不变量

- Trusted Hub / Untrusted Agent 分离：Hub 控制层、Grant、可信存储、Git Broker 和秘密管理不应暴露给 Agent 执行进程任意写入。
- 只有同时处于有效 Grant 与已验证能力范围内的操作，才能实际执行；模型建议、文档和互操作协议都不能自行授予权限。
- 文件访问、网络外发、凭据使用及 IPC 是需要分别控制的权限面；localhost 不等于可信。
- 已确认 Intent、意图修改授权、人工审批与可信验收不能由不可信指令篡改；恢复不能绕过授权失效，也不能把未经用户授权的目标修订变成有效意图。
- 验证条件失效时限制受影响能力，不继续沿用过期安全结论；中断时核查实际副作用。

领域记录与外部事实的权威边界以[治理文档](governance.md#权威事实源与持久化边界)为准。

## macOS Sandbox：待验证的执行机制

首版主要面向 macOS 本地执行，优先评估原生 Seatbelt / sandbox-exec 等受限进程机制；可参考 Anthropic Sandbox Runtime、Codex 的已有实现。参考对象不是已选依赖，也不代表兼容性或安全性已被证明。

候选机制需要同时允许获准的文件操作、测试、子进程、临时资源和正常停止，并阻断越权路径。路径绕过、子进程扩权、网络、IPC、初始化失败和残留进程均属于验证面。正式用例范围见[X1 契约](validation.md#x1-验证契约)。

Sandbox 初始化失败、环境不匹配或相关验证条件失效时，不得静默退回无约束执行。首次高风险验证需要独立外层保护，不能由尚未证实有效的候选 Sandbox 自我保护。

## Trusted Git Broker：受限的 Git 权限入口

Agent 直接修改授权工作文件，而 Git 管理状态具有影响提交与权限的额外能力，因此由可信 Broker 负责受限管理状态修改和获准本地 Commit。

Broker 必须关注：

- Git Common Directory、Gitdir、Refs、Index 与 Config 的保护边界。
- Hook / Filter 引出的额外执行及间接权限。
- 提交内容是否被授权，是否与实际交付内容一致。
- 并发修改、提交结果未知及结果记录中断。
- 远程凭据和远程操作越权。

Broker 不能成为任意高权限 Git 命令转发器。本地 Commit 的授权不包含 Push、PR、Merge 或 Release。Hub 负责提交推送和读取 CI 的产品决策，不会自动扩大 Broker 的权限或证明远程执行能力已验证；实际启用所需的凭据、网络、远程操作和恢复边界须另行验证，并由适用 Grant 覆盖。

受保护 Worktree 是需要验证的方案；如果不能满足强制要求，只能依据失败证据提出独立 Git 元数据副本的回退选项。重大架构改道须人工批准，当前未选定回退实现。正式验证面见[X2 契约](validation.md#x2-验证契约)。

## 凭据、网络与 IPC

模型 API Key、SSH 凭据及其他秘密必须与 Agent 执行进程隔离。Hub 调用模型不意味着 Agent 执行进程可以读取或使用模型 API Key。

网络外发与文件权限分开授权；文件可读不自动意味着可以发送到网络。本地 Socket、SSH Agent、Credential Helper 等高权限通道不能因为位于 localhost 就默认可信。X3 应检验凭据、网络、IPC 与间接权限，必要时与 X1/X2 检查组合越权路径。

本文件不预选凭据存储产品、网络代理、IPC 白名单或具体策略语法。CI 结果和应用运行结果服务于交付判断，不能代替这里的执行隔离、秘密保护与权限验证。

## 中断、恢复与能力降级

取消或进程终止可能留下子进程、文件变化、Git 提交或未记入 Hub 的副作用，因此“停止返回”本身不足以证明安全结束。

恢复必须依据真实外部状态和可信观察，核查残留执行、未知副作用、当前 Grant 和 Evidence 适用性；不能直接宣称回滚或盲目重试。受保护写入、撤销、备份恢复和敏感信息清理仍需 X4/X5 证明。

能力可按真实验证情况处于 **Controlled、Restricted、Advisory** 等已确定等级；可用性必须绑定验证过的环境、策略和组件版本。重要条件失效时限制受影响能力。当前没有任何已验证等级分配，本摘要也未给出各等级的完整判定阈值，不在文档中补造。

## 首次实验及晋升边界

首次高风险实验优先使用可丢弃 macOS VM 或经审查的等效独立外层保护，并使用模拟仓库、模拟秘密与受控网络。即使候选 Sandbox 失效，也不应直接威胁真实宿主机。

Guest 验证通过不自动取得宿主机执行资格；X1 和 X2 分别 Pass 也不自动证明组合安全。候选组件必须在真实版本、运行环境和策略下验证，并经可信晋升，才能承担正式职责。

实验启动条件、退出状态和四层准入见[验证文档](validation.md)。本次不配置任何 Sandbox、VM、Broker 或网络策略。
